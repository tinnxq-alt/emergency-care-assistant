# 急救诊疗助手

面向基层急诊、抢救与值班场景的静态 PWA 工作台。

## v0.20 当前能力

- 首页、急症、急救流程、用药和待办五个独立入口。
- 10 个高频急救流程导航，关联既有临床主题与药物检索。
- 临床内容显示 `verified / verified-partial / source-bound` 等核验状态。
- 本院抢救车 18 项和病房药库 164 种药品只表达可获得性，不改变指南优先级。
- 抢救车不设置“正常 / 待补 / 缺货 / 已停用”等库存状态。
- 待办和本机编辑只保存在当前浏览器，不上传患者信息。
- 支持安装和离线访问；离线缓存对页面与静态资源分别处理。

## 临床安全边界

流程页是快速导航层，不替代临床判断、院内制度或上级医师意见。具体剂量、浓度、配液、泵速、禁忌证和操作参数，只能在可靠来源及本院流程完成核验后固化。`本院有药` 仅代表可获得性。

## 基层临床助手融合状态

- v0.20 的 10 个急救流程共引用 12 个不同药名。
- 已与基层用药助手稳定药库完成只读匹配审计：阿司匹林、葡萄糖、头孢曲松 3 项得到唯一 `drug_id`。
- 肾上腺素、胺碘酮等 9 项尚未进入统一药品目录，明确保持阻塞；不得按名称猜测 ID。
- `drug-id-migration-v020.js` 保存迁移结论和基线提交，不修改现有流程显示或临床内容。
- 下一步应先把缺失抢救药物纳入统一药品注册表并完成规格、来源与库存审核，再切换运行时引用。

## 开发与检查

```text
npm test
```

该检查会验证所有页面的本地资源、基础可访问性标记、PWA 离线清单和版本描述。GitHub Actions 会在 PR 和目标分支更新时自动执行。

`main` 继续作为稳定基线；改动应先进入审核分支和 Draft PR，通过自动检查与人工临床审核后再合并。
